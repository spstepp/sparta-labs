How do ABA providers catch sessions that don't match an authorization?

A session should match an authorization on three things: the client, the CPT code and the date. If the code is wrong, the date falls outside the authorized period, or the client has no active authorization for that code, the session doesn't belong in that pool of units. Checking this as you log sessions, not after a claim comes back, is how you catch the mismatch while it's still easy to fix.

How to set it up

  1. Keep one authorization row per client per CPT code, with the units approved and the start and end dates from the payer's letter.
  2. Log each session with the client ID, CPT code, date, units, provider and status (scheduled, completed or cancelled).
  3. Treat a session as a match only when the client and CPT code agree and the date sits between the authorization's start and end. Direct treatment, protocol modification, parent training and assessment are usually separate pools, so a 97153 session does not use 97155 units.
  4. Flag anything that doesn't match: an unknown client ID, a missing status, a date outside the authorized period, or a code with no authorization row.
  5. Fix the row before it's billed. The usual causes are a typo in the code, a session logged under the wrong client, an authorization that hasn't been entered yet, or a date that belongs to the next (or last) authorization.
  6. Also watch active clients who have no current authorization for the codes you are scheduling, so gaps show up before the week is booked.

Authorization terms, covered codes and what you may bill come from each payer and plan. This is a record-keeping check, not billing advice. Verify each authorization with your payer and follow your organization's billing rules.

Common follow-up questions

What if a new authorization starts before the old one ends?

A session that falls inside both date ranges can count toward both. Start the new row the day after the old one ends, or set the dates to match what your payer approved.

The payer authorized hours, not units. Does the same check work?

Yes, as long as you enter sessions and authorizations in the same measure. Many practices convert hours to 15-minute units (multiply by 4) and stay with units for that code.

Should cancelled sessions be flagged?

Cancelled sessions don't use units, but they still need a client, code, date and status in the log. A missing status is worth flagging, because an unlabeled row can't be counted or excluded on purpose.
